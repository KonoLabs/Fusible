# Fusible

> **The fuse for your firmware.** An electronic linter in Rust: it reads the
> Circuit JSON generated by [tscircuit](https://tscircuit.com), checks the
> electrical and physical rules of the board — and when a rule fails, **the
> fuse blows**: the process exits with an error and firmware code generation
> never happens.

Rather than letting a broken circuit reach the firmware, Fusible reports
compiler-style diagnostics (`miette`), pointing at the faulty line in the
source file.

## Installation

```sh
cargo install --path .
# or grab an archive from the GitHub releases
```

## Usage

```sh
fusible --input circuit.json --mcu stm32g431
```

Clean circuit:

```
✅ Circuit validated (fuse intact)
```

Rule violated (exit code 1):

```
× the fuse blew: 1 electrical violation(s)
× [unconnected_net] net "I2C_SDA" has only 1 connection(s) (minimum 2): it is floating
  help: every net must connect at least two pads/ports — complete the routing in tscircuit
```

Malformed JSON (exit code 2):

```
× invalid Circuit JSON: expected `,` or `}` at line 4 column 1
   ╭─[circuit.json:4:1]
 4 │ ]
   · ┬
   · ╰── deserialization failed here
```

Three examples ship in [`examples/`](examples/): `circuit.json` (fuse
intact), `circuit-floating.json` (fuse blown) and `circuit-broken.json`
(parse error).

## Exit codes

The codes are part of the contract, so CI can tell failures apart:

| Code | Meaning |
|---|---|
| `0` | Fuse intact — the circuit validated |
| `1` | Electrical violations — the fuse blew, generation is blocked |
| `2` | Tool or usage error (unreadable/malformed input, bad arguments) |

## Architecture

```
src/
├── main.rs                 # read → parse → lint → verdict, exit codes
├── cli.rs                  # clap: --input, --mcu
├── parser.rs               # internally tagged Serde enum + Circuit AST
│   ├── diagnostic.rs       # miette rendering of parse errors
│   └── tests.rs
├── linter.rs               # Rule trait + Linter registry
│   ├── diagnostics.rs      # Diagnostic / FuseBlown (miette)
│   ├── rules.rs            # one rule per file
│   │   ├── unconnected_net.rs
│   │   ├── malformed_element.rs
│   │   └── ghost_net.rs
│   └── tests.rs
tests/
└── exit_code.rs            # the 0 / 1 / 2 contract
```

The tscircuit Circuit JSON is an array of heterogeneous objects
discriminated by a `type` field: Serde deserializes it through an
internally tagged enum, and unmodeled types are *skipped* rather than
rejected — the fuse only blows on real electrical violations. Identifiers
missing from recognized elements are violations too (`malformed_element`),
so the linter is fail-closed: it never validates input it could not read.
