# AGENTS.md — Fusible Agent Guide

> **The fuse for your firmware.** Fusible is an electronic linter and tscircuit project manager written in Rust. It reads the Circuit JSON generated by [tscircuit](https://tscircuit.com), checks physical and electrical design rules, and enforces a strict contract: **when a rule fails, the fuse blows (exit code 1)** — halting artifact exports and firmware code generation before defective designs can reach fabrication.

---

## 1. Project Philosophy & Invariants

1. **The Fuse Contract (Exit Codes)**:
   - `0` — **Fuse intact**: circuit is electrically sound, rules pass, command succeeded.
   - `1` — **Fuse blown**: one or more electrical violations detected (`unconnected_net`, `ghost_net`, `shorted_nets`, `malformed_element`, `trace_clearance`, `pin_mux`, `harness_mismatch`). Artifact exports and codegen are blocked.
   - `2` — **Tool error**: IO failure, unreadable/malformed JSON, runner missing, or CLI syntax error.
2. **Fail-Closed Rule Design**: If a net or component cannot be definitively proven connected, report it. Never assume floating traces or unlinked ports are valid without explicit net aliases.
3. **Rust Core / External Toolchain Separation**:
   - The core parser (`src/parser/`), netlist IR (`src/netlist/`), and rules engine (`src/linter/`) are 100% pure Rust with zero C-system dependencies.
   - External EDA converters (Gerber, SVG, STEP, KiCad) and the dev server are orchestrated through `src/tscircuit/` via local `tsci`, `bun`, `npx`, or `npm`.
   - If `tscircuit` is not installed on the host machine, Fusible continues to function gracefully by leveraging existing `circuit.json` or providing `fusible doctor`.

## 3. Standard Development Workflow

Before submitting any change, run:

```sh
# 1. Format check
cargo fmt --all -- --check

# 2. Clippy lint (zero warnings permitted)
cargo clippy --all-targets -- -D warnings

# 3. Test suite
cargo test --locked

# 4. Suite quality check (filet.yml at the root; must report nothing)
filet check .
```

Commit messages MUST adhere to [Conventional Commits](https://www.conventionalcommits.org/):
- `feat:` new feature or CLI command
- `fix:` bug fix or rule correction
- `chore:` release, dependencies, toolchain updates
- `docs:` documentation or comments

## 4. Fusible CLI Commands Reference

- `fusible check [TARGET] [--mcu <MCU>]`: Runs the electrical linter on a board name, Circuit JSON, or TSX file. Without a target it checks every board of `fusible.yml`. Falls back to cached `dist/circuit.json` if runner is absent.
- `fusible dev [FILE] [-p <PORT>] [--desktop]`: Launches interactive hot-reloading webview. `--desktop` prints one `FUSIBLE_READY {"url","port"}` line when bound, exits 0 when stdin closes, and adds a Projects button to the studio dock.
- `fusible export [FILE] [--preset <PRESET>] [-f <FORMAT>] [-o <PATH>]`:
  - **Fuse-gated**: Validates rules before creating any files.
  - `--preset fab`: Exports `gerbers.zip` and `circuit.json` into `dist/fab/`.
  - `--preset cad`: Exports `kicad.zip` and `board.step` into `dist/cad/`.
  - `--preset docs`: Exports `schematic.svg`, `pcb.svg`, and `schematic.pdf` into `dist/docs/`. The PDF needs a local Chromium; without one it warns and writes SVG only.
  - `--preset all`: Runs all three presets.
  - `-f <FORMAT>`: Direct export (`gerbers`, `pcb-svg`, `step`, `glb`, `kicad_zip`, etc.).
  - `--skip-lint`: Bypasses electrical rule checking (for drafts only).
- `fusible body [TARGET]`: Builds physical bodies. A body is authored (`source:`, optional `build:` command) or generated (`generate: enclosure`, fuse-gated). TARGET is a body name or a board.
- `fusible assembly [-f glb|step|all] [-o DIR] [--skip-lint]` (alias `asm`, `src/commands/assembly/`): places the `assembly:` parts in one frame and writes `assembly.{glb,step}`. Fuse-gated over every board it draws or fits a generated body to. A board needs a TSX entry and a runner (its STEP comes from `tsci export`); a generated body is shifted by `-(board_z + thickness/2)` so its frame matches tscircuit's board frame (mid-plane at Z = 0). Transforms are 3x4 row-major in `place.rs` (no IO, reused by the future cross-world rules); `src/assets/assembly.ts` only applies them and merges.
- `fusible bom [TARGET] [-f table|csv|json] [-o PATH]`: Bill of materials from the placed components, the bodies as prints, and `bom.yml` (prices, picks, manual parts). Never blows the fuse.
- `links:` (`src/config/types.rs`, `src/commands/{links,harness}.rs`): board-to-board wires. `check_manifest_links` in `src/commands/check.rs` runs `harness_mismatch` after the boards, only when every board was checked. A missing part, missing pin, or floating pin fails closed.
- `fusible doctor [--install] [--json]`: Inspects bun/node/npm/tsci toolchains and optionally provisions `tscircuit`. `--json` prints `{"bun","node","tsci"}` (`{path, version}` or null) and exits 0. Env `FUSIBLE_BUN` overrides the bun lookup everywhere; without a `tsci`, the runner falls back to `bun x --bun tsci`.
- `fusible init [--name <NAME>] [--currency <CODE>]`: Generates a clean `fusible.yml` project manifest. `--currency` also writes `bom.yml`.
- Studio `SYNC` panel (`src/assets/git.js`, `src/dev/git_*.rs`): git for non-developers. Every git call goes through `Git::run` in `src/dev/git_run.rs` (real binary, no shell, 30 s deadline, `GIT_TERMINAL_PROMPT=0`, no credential reads). `GET /api/git`, `POST /api/git/{save,update,resolve}` share the `/api/run` same-origin and JSON guard. UI wording: Sync, Save, Get updates, Saves; never commit, push, pull, rebase, or stage outside error details. During a rebase, `--ours` is the other person's side, so Keep mine is `--theirs` (see `git_resolve::flag`). Tests build two clones of a bare repo in a temp dir (`git_support.rs`).
- Studio KiCad watch (`src/dev/kicad_*.rs`, `src/kicad/{live,tsx,tsx_tag,changes,nets,backup,locate}.rs`, `src/assets/kicad.js`): per-board `kicad:` key (fallback: the single `.kicad_pcb` beside the entry or in `kicad/`). A debounced watcher on that file runs `compare_board`, then `sync_positions`, which rewrites literal `pcbX`/`pcbY`/`pcbRotation` props in the TSX tree after copying each file to `.fusible/backup` (10 kept). Parts and net changes are only reported (`design_differences`). `compare_board` fails closed on unparseable Circuit JSON. Linux raises watch events for plain reads, so every watcher filters through `Stamps` (`src/dev/stamps.rs`) and reacts only to a changed mtime or size; keep that filter or a rebuild that reads its sources will rebuild forever. Status: `GET /api/kicad` and a `{"event":"sync"}` message on `/events`.
